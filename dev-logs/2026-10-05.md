### 阶段 A（ESP32 烧录）：定位并修复「开机即崩」的真正根因

**症状**：ESP32-C3（合宙经典款）烧录后无限重启，串口循环输出：
`assert failed: tcpip_send_msg_wait_sem ... (Invalid mbox)`（lwIP tcpip.c）。

**排查过程（关键转折）**：
1. 先怀疑 core 3.0.7 + Arduino IDE 1.8.19 不兼容 → 降级 core 到 2.0.17（手动组装：
   git clone 官方 2.0.17 仓库，预编译库 tools/sdk 就在仓库内，无需下载 esp32-arduino-libs；
   riscv32-esp-elf-gcc 8.4.0 走 Espressif 官方镜像 dl.espressif.cn/github_assets，SHA-256 校验通过）。
   但 **2.0.17 下崩溃依旧**（tcpip.c 行号 449→455）→ 环境不兼容假设**被推翻**。
2. 抓完整启动串口：崩溃前**没有任何输出**。而 sketch 里 connectWiFi() 第一行就是 printf——
   说明崩溃点在 connectWiFi **之前**。
3. 锁定 setup() 里 `coapUdp.begin(5683)` 位于 `connectWiFi()` 之前。查源码
   `libraries/WiFi/src/WiFiUdp.cpp`：`WiFiUDP::begin()` 走 lwIP BSD socket API，
   会向 lwIP tcpip 线程发消息（tcpip_send_msg_wait_sem），此时线程未启动 → mbox 无效 → 断言崩溃。

**真正根因**：固件初始化顺序 bug——设备间联动的 UDP 监听（`coapUdp.begin(5683)`）在
`WiFi.mode/begin` 之前执行，lwIP 栈尚未初始化。

**修复**：把 `coapUdp.begin(5683)` 移到 `connectWiFi()` 之后。
- `edge/esp32/community_device/community_device.ino`
- `edge/esp32/camera_device/camera_device.ino`（同样的 bug）
- 同时恢复诊断时临时移除的静态 IP（`WiFi.config(STATIC_IP, GATEWAY, SUBNET)`）与
  发射功率（`WiFi.setTxPower(WIFI_POWER_8_5dBm)`）。

**验证**：light-01 重新烧录后不再崩溃，串口正常输出
`连接 WiFi → WiFi 连接失败（热点未开）→ MQTT 连接失败, 重试...`，无 assert / Reboot。

### 遗留问题（后端测试失败）排查与修复

后端全量测试从 33 失败修到 0 失败（267 passed）。根因分三类：

1. **版本 9→10 漂移**：设备图工作新增 `V3_DEVICE_RISK_MIGRATION`（版本 10），但维护代码 `v3_db_maintenance.py` 与大量测试仍硬编码「版本 9 为最高」。→ 维护代码改为从 `V3_MIGRATIONS` 动态推导最新版本；更新所有 `[1..9]`/`== 9`/`applied_versions`/`list(range(1,10))` 断言为含版本 10。
2. **`sqlite3.SQLITE_*` 常量被移除**：本机 Python 的 sqlite3 模块已删除 `SQLITE_BUSY/LOCKED/READONLY/FULL/CORRUPT/NOTADB/CANTOPEN/IOERR` 常量，导致 `_sqlite_reason` 抛 `AttributeError`（连带 DB 锁检测、bootstrap 回滚失败）。→ 三个文件（`runtime_services.py`/`v3_admin_bootstrap.py`/`v3_db_maintenance.py`）改用标准 SQLite 数字结果码（5/6/8/13/11/26/14/10）。
3. **过时测试/夹具**：app_factory 蓝图集缺 `detection`、`/api/capture/start` 被误列为应删除、`capture_service` 旧断言、`edge_detect.py` 已改风险上报不再是流量探针、retention 已不清理 legacy `traffic_logs`、realtime 设备夹具缺风险字段。→ 逐一更新测试/夹具以匹配当前实现。

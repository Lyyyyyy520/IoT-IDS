## 阶段 1：v3 设备状态数据基础

- 增加临时 SQLite 测试，覆盖建表共存、幂等初始化、身份冲突、IP 变化、超时边界、维护模式和重启预热。

## 阶段 1：显式 v3 数据库升级命令

### 已完成

- 新增 `plan`、`backup`、`apply` CLI，数据库路径和备份目录均必须显式传入。
- `plan` 使用 SQLite 严格只读 immutable 模式；活动 WAL/journal 必须先生成一致性副本。
- `apply` 在修改前后执行完整性检查，并使用 SQLite backup API 创建和验证 WAL 兼容备份。
- 新增 `v3_schema_migrations`，按版本、名称和 checksum 幂等登记迁移。
- 所有 schema 语句和迁移登记处于同一事务；失败回滚且保留修改前备份。
- 旧 `assets` 的重复、缺失和无效 MAC/IP 只进入 plan 报告，不自动导入。
- 测试全部使用临时 SQLite，覆盖只读计划、错误输入、备份、WAL、幂等、冲突报告和事务回滚。

## 阶段 1：MQTT 心跳 v2 与纯 ingestion

### 已完成

- 固定 MQTT 心跳 schema v2，增加 boot ID、递增 sequence、固件版本、运行时 IP/MAC 和嵌套 telemetry。
- 两套 ESP32 固件使用相同信封；每次启动生成随机 boot ID，串口不打印完整 payload。
- 新增 migration v2，保存 boot 会话、当前游标和观测证据；migration v1 checksum 保持不变。
- 新增不依赖 MQTT 网络客户端的 validator/ingestor，可直接注入 topic、payload 和后端接收时间。
- 未登记设备不自动信任；topic/ID/MAC、消息大小、UTF-8、JSON、字段和范围全部校验。
- 同 boot 重复/乱序、新 boot 重置、旧 boot 重放和 uptime 倒退均有明确结果，拒绝消息不刷新在线时间。
- 本轮未连接真实 Broker，所有数据库测试继续使用临时 SQLite。

## 阶段 1：托管 MQTT 心跳订阅客户端

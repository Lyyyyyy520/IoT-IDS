# 2026-10-10 开发日志

## 摄像头固件改为真实视频流（去舵机）

用户要求：摄像头不要云台舵机，画面要显示在前端。

### 固件 `edge/esp32/camera_device/camera_device.ino`（v0.4.0）

- **去掉舵机**：删除 `ESP32Servo`、`PAN_PIN`、云台扫描/乱转/回正全部逻辑。
- **新增真实画面**：引入 `esp32cam` 库（yoursunny，自带 OV2640 驱动），
  HTTP 服务在 80 端口：
  - `GET /stream` —— MJPEG 视频流（前端 `<img>` 直连）
  - `GET /capture` —— 单帧 JPEG（调试用）
  - `GET /` —— 极简页面内嵌 stream（浏览器直接看）
- **保留 IDS 能力**：MQTT 心跳 schema v2、CoAP 门禁联动、LINK_SIM_MODE 周期出向、
  攻击模拟（只打 .200:9000，30s 自动停）全部保留。
- **关键点（推流期间不掉线）**：`handleStream` 是阻塞循环，每帧之间调用
  `serviceHousekeeping()`（内含 `mqtt.loop()` + 遥测 + 联动 + 攻击），
  否则推流期间后端会把摄像头判离线。

### 依赖与编译

- 安装 `esp32cam@0.0.20250112`（`arduino-cli lib install esp32cam`）。
- **C++17 坑**：esp32cam 库用了 `std::enable_if_t`/`is_assignable_v`（C++14/17），
  而 esp32 core 2.0.17 默认 `-std=gnu++11`。用
  `--build-property "compiler.cpp.extra_flags=-std=gnu++17"` 覆盖（platform.txt 的
  `recipe.cpp.o.pattern` 里有 `{compiler.cpp.extra_flags}` 空槽位，追加后 GCC 后者生效）。
- 编译通过：Flash 893433B(28%)，RAM 50648B(15%)。
- 烧录脚本 `edge/esp32/flash_camera.sh`（无参=只编译+列串口；`COM4`=编译+烧录）。

### 前端 `frontend/.env.local`

- 已有 `CameraPreviewPanel` 支持 `VITE_CAMERA_STREAM_URL_TEMPLATE`（含 `{ip_address}` 占位）。
- 新增 `.env.local`：`VITE_CAMERA_STREAM_URL_TEMPLATE=http://{ip_address}/stream`，
  摄像头面板即加载 `http://192.168.4.10/stream`。`.local` 已被 `.gitignore` 忽略。

## 规则签名层 + 现场演示闭环

### `backend/services/rule_engine.py`（新增）

- Mirai 规则签名：内网 SYN 扫描（23/2323/80）、外网 UDP 洪水（排除 53/123）、
  C2（10.99.1.100:443）、**受害机洪水（.200:9000，现场演示主签名）**。
- `IOT_IDS_RULE_SIGNATURES=victim_flood`：现场演示只用受害机洪水签名——
  真实抓包下 udp_flood/syn_scan 对正常设备（mDNS/QUIC/相机 10.0.0.1 上行）噪声大，会误报。

### `backend/services/traffic_capture.py`

- 规则融合 `IOT_IDS_RULE_FUSION=on`：命中签名→强制红(3)；未命中→强制绿(0)。
  （现场演示 6 台规模 GNN 退化为稀疏图、正常流量被误判黄，风险等级由规则层红/绿二态决定。）
- 自动检测 `IOT_IDS_AUTO_DETECT=off`：关闭按窗口周期自动重判，判红后锁住直到人工处置。
- 后端测试 `backend/tests/test_rule_engine.py`（23 个用例）。

### 现场联调（6 台物理设备）

- Pi 热点 + Mosquitto + 后端 + 前端 + 受害机 .200（Pi 加 IP 别名 + `edge/victim_udp_counter.py`）。
- 攻击闭环：`attack` → 门禁舵机开门 + UDP 洪水 → scapy 抓 wlan0 → 受害机洪水签名 → 判红。
- **踩坑**：Pi 重启后 (1) 双 hostapd 抢 wlan0（旧 `/etc/hostapd` 服务未禁用，已 `systemctl disable`）；
  (2) SQLite 残留 `-journal` 导致 database_read_only（重启后回滚恢复）；(3) 设备序列号涨高导致
  invalid_initial_sequence（需后端就绪后设备断电重启）。

## 1. 方案概述

用 **6 台物理 ESP32 + 30 台虚拟设备** 模拟一个"3 栋楼 + 公共区域"的小型智慧社区，让设备图从"7 节点星型"扩展为"37 节点丰富拓扑"，从而：

1. **稀释图污染**（一台攻击者在 36 台设备里的相对影响变小）
2. **更贴近真实社区**（设备构成、联动关系都符合真实 IoT 逻辑）
3. **契合训练集规模**（CICIoT2023 有 105 台，我们 36 台 ≈ 1/3）

**架构选择**：虚拟设备跑在**本地电脑**（而非树莓派），因为：
- 树莓派方案有"回环问题"（虚拟设备的 MQTT 流量是本地回环，不经过 wlan0，scapy 抓不到）
- 电脑是独立 WiFi 客户端，流量真实穿过 WiFi 到树莓派 wlan0，全被抓到（和物理设备一致）
- 分离架构是 2024 年测试床文献的标准做法

## 3. 网络拓扑关系图

```
                          [ 外网 / 云 8.8.8.8 ]
                               ^
                               | HTTP / 视频流 (摄像头)
                               | DNS / NTP (所有设备)
                     +--------------------------+
                     |      网关 树莓派           |
                     |      192.168.4.1          |
                     |  (MQTT broker + 检测者)    |
                     +--------------------------+
                               ^
                               | MQTT 遥测 (所有设备周期上报)
         +---------------------+----------------------+
         |                     |                      |
   +-----------+        +-------------+        +-------------+
   | 物理设备    |        | 虚拟设备     |        | 虚拟设备     |
   | .10 ~ .15  |        | 楼栋 1-3     |        | 公共区域     |
   | (6 台)     |        | (22 台)      |        | (8 台)      |
   +-----------+        +-------------+        +-------------+

  ── 设备间联动（CoAP 直连，不过网关）─────────────────────────
  门磁 (.104-.109)      ──CoAP──>  楼道灯 (.113-.121)    门开 → 灯亮
  烟雾 (.110-.112)      ──CoAP──>  门禁 (.11)+楼道灯      火灾 → 解锁+照明
  温湿度 (.14/.102/.103) ─CoAP──>  插座 (.13/.126-.128)   温度高 → 空调
  门禁 (.11/.100/.101)  ──CoAP──>  音箱 (.15/.129)        门开 → 广播
```

**三类边**：
1. **设备 → 网关**（MQTT，所有设备）—— 主通信，形成"星型 + 遥测"
2. **设备 → 设备**（CoAP，传感器→执行器）—— 联动，打破纯星型
3. **摄像头 → 云**（HTTP）—— 视频流上传

## 5. 设备间联动关系（完整表）

| 联动 | 触发 | 源设备 | 目标设备 | 协议 | 真实场景 |
|------|------|--------|---------|------|---------|
| 门磁 → 楼道灯 | 单元门开 | 门磁(虚拟) | 同楼栋楼道灯 | CoAP | 有人进出自动亮灯 |
| 烟雾 → 门禁 + 楼道灯 | 检测到烟 | 烟雾(虚拟) | 同楼栋门禁+楼道灯 | CoAP | 火灾解锁+逃生照明 |
| 温湿度 → 插座 | 温度过高 | 温湿度 | 同楼栋插座 | CoAP | 高温自动开空调 |
| 门禁 → 音箱 | 门被打开 | 门禁 | 音箱 | CoAP | 开门广播提示 |
| 摄像头 → 网关 → 云 | 持续 | 摄像头 | 云 | HTTP | 视频流上传 |

> **同楼栋原则**：联动关系限定在"同一楼栋内"（门磁只触发本楼栋的灯），符合真实物理逻辑。

## 6. IP 分配

| 范围 | 用途 |
|------|------|
| .1 | 网关（树莓派） |
| .10~.15 | 物理设备（6 台，静态 IP） |
| .100~.129 | 虚拟设备（30 台，电脑多 IP 绑定） |

DHCP 范围需排除 `.10~.15` 和 `.100~.129`。

## 8. 方案合理性

1. **规模合理**：3 楼栋 + 公共区域 = 36 台，是"小型小区"的真实比例（传感器/灯多、网关少）
2. **联动真实**：门磁→灯、烟雾→门禁/灯、温湿度→插座，都是真实社区的标准安防/节能联动
3. **同楼栋原则**：联动限定在楼栋内，符合真实物理逻辑
4. **文献对齐**：分离架构（虚拟设备在电脑、IDS 在树莓派）是 2024 年测试床标准做法

## 1. 概述

树莓派 = **边缘智能网关 + 社区安全机器人**，是整个智慧社区的"大脑和神经中枢"。

**核心叙事（一句话）**：

> 我们部署了一个"社区安全机器人"（树莓派），它用**设备图神经网络**实时守护智慧社区，通过**数字孪生**看清每台设备的状态，用**语音**播报攻击并**自动隔离**受感染的设备。

机器人是 P1 的"震撼演示"增强项：让检测结果从屏幕上的颜色，升级为"看得见、听得见、指得到"的三模态反馈。**P0 核心闭环（检测→隔离）不依赖机器人**，所以当前先不实现，只保留本方案待后续落地。

## 3. 树莓派的七大职能

| 职责 | 干什么 | 对应代码 |
|------|--------|---------|
| ① 网络网关 | ESP32 都连 Pi 的热点，所有流量必经 Pi | 网络配置（hostapd + dnsmasq） |
| ② 流量采集 | 嗅探全网数据包 | `traffic_capture.py` |
| ③ 特征提取 + 建设备图 | 原始包 → 设备级特征 + 设备通信图 | `cicids_feature_extract.py` + 设备图模块 |
| ④ 模型推理 | 加载 ONNX GNN，实时推理设备风险等级 | `gat_inference.py` + 设备图 GNN |
| ⑤ 响应执行 | 隔离被感染设备（网络 + 物理两级） | 响应模块（iptables + MQTT） |
| ⑥ 蜜罐宿主（可选） | 跑假漏洞服务诱捕攻击 | 蜜罐模块 |
| ⑦ 机器人交互 | 数字孪生屏 + 语音播报 + 指向 | 交互模块 |

**关键：树莓派必须自己开热点当网关**，否则设备间通信抓不到，IDS 失效。

## 4. 语音播报设计

语音用 USB 音箱 + edge-tts（或离线 TTS）合成，针对性播报（机器人"张嘴说话"）：

```
"⚠️ 检测到 3 号设备——智能摄像头，疑似被僵尸网络感染。"
"风险等级：红色，最高级。正在隔离该设备……"
"隔离完成，社区网络已恢复安全。"
```

按风险等级播报（映射分级响应 L1/L2/L3）：

| 风险等级 | 风险色 | 语音播报 |
|---------|--------|---------|
| 1 侦察 | 🟡 黄 | "发现可疑扫描，正在观察" |
| 2 拒绝服务 | 🟠 橙 | "检测到洪水攻击，已限流" |
| 3 僵尸网络 | 🔴 红 | "检测到僵尸网络感染，正在隔离" |

## 5. 数字孪生屏显示

机器人的"眼睛"（HDMI 屏）显示**数字孪生拓扑图**，与电脑端（React）、APP 端（Expo）三屏联动：

| 显示内容 | 说明 |
|---------|------|
| 设备拓扑图 | 6 台社区设备 + 网关，实时风险色（🟢🟡🟠🔴） |
| 机器人表情 | 平静（全绿）/ 警觉（发现异常）/ 严肃（隔离中） |
| 告警横幅 | 被感染设备高亮 + 处置状态 |
| 处置日志 | 检测→隔离的完整时间线 |

**实现方式**：后端 Flask 用 WebSocket/SSE 广播实时数据，三端同时订阅，实现"三屏联动"。

## 8. 与核心检测的解耦说明

机器人是**纯展示层增强**，与检测引擎（`traffic_capture.py` → 设备图 GNN → `device_detector.py`）完全解耦：

- 检测引擎只负责"抓包 → 建图 → 推理 → 输出风险等级"，输出为标准化的设备风险列表。
- 机器人交互层只负责"订阅风险列表 → 屏显 + 语音 + 指向"，替换/停用都不影响检测。
- 因此机器人可随时在 P0 之后再补，不影响核心演示闭环。

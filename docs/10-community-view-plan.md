# 10 - 智慧社区数字孪生视图方案（web + app）

> 状态：方案设计稿（待实施）
> 更新日期：2026-08-30
> 关联文档：[06-demo-design.md](06-demo-design.md)、[07-device-topology.md](07-device-topology.md)、[09-deployment-checklist.md](09-deployment-checklist.md)

## 1. 目标

在 **web 端（React）和手机 APP 端（Expo）** 同时显示智慧社区的 6 台 IoT 设备状态，摄像头显示拍摄画面，形成"数字孪生"视图，作为现场演示的核心展示页。

## 2. 可行性分析

| 需求 | 可行性 | 说明 |
|------|--------|------|
| 6 设备状态显示（web + app） | ✅ 完全可行 | 后端已有 `/api/device/status` + `device_risk_cache` |
| 摄像头画面（web + app） | ⚠️ 有条件可行 | 需 ESP32-CAM + 前端能访问摄像头 IP（同网络） |
| 实时同步 | ✅ 可行 | 轮询（简单）或 WebSocket |
| 被入侵画面"劫持"效果 | ✅ 可行 | 前端叠加效果（红框 + HACKED 文字） |

**结论**：6 设备状态 + 风险等级显示**现在就能做**（已有 5 台 ESP32-C3 + 后端数据）。摄像头画面需 ESP32-CAM（未购），但可先做占位图，到货后接流地址。

## 3. 摄像头画面方案

ESP32-CAM 用标准 MJPEG 流（CameraWebServer 示例）：

| 方案 | 做法 | 优点 | 缺点 |
|------|------|------|------|
| **A. 直连 MJPEG 流（推荐）** | 前端 `<img src="http://192.168.4.10:81/stream">` | 最简单，零后端改动 | 前端需和摄像头同网络 |
| B. 后端转发 | 后端拉流再转发 | 集中管理 | 复杂，带宽翻倍 |
| C. 快照轮询 | 摄像头定时拍照，后端取图 | 省带宽 | 有延迟 |

**推荐方案 A**：演示时设备+电脑+手机都在 Pi 热点（192.168.4.x）同一网络，前端直接嵌流地址。摄像头未到时用占位图，到货后换流地址（一行改动）。

**被入侵画面劫持效果**：摄像头正常=实时画面+绿框；检测到感染（红色风险）=前端叠加红框 + "⚠️ HACKED" 半透明覆盖层（纯前端效果，不真改摄像头）。

## 5. 技术落地方案

### 5.1 后端（改动小）

新增 `/api/community/devices` 接口，返回 6 台设备的信息 + 实时风险等级 + 摄像头流地址：

```python
COMMUNITY_DEVICES = [
    {'id':'camera-01','name':'智能摄像头','type':'camera','ip':'192.168.4.10','stream':'http://192.168.4.10:81/stream'},
    {'id':'door-01','name':'智能门禁','type':'door','ip':'192.168.4.11'},
    {'id':'light-01','name':'智能路灯','type':'light','ip':'192.168.4.12'},
    {'id':'plug-01','name':'智能插座','type':'plug','ip':'192.168.4.13'},
    {'id':'sensor-01','name':'温湿度传感器','type':'sensor','ip':'192.168.4.14'},
    {'id':'speaker-01','name':'智能音箱','type':'speaker','ip':'192.168.4.15'},
]
```

接口把 `device_risk_cache`（IP→风险）和上面信息合并，返回：

```json
[{"id":"door-01","name":"智能门禁","type":"door","level":0,"level_name":"正常","confidence":0.98}, ...]
```

### 5.2 前端（web + app 各加一个社区视图）

- **React web**：新增 `Community` 页面（或升级 Dashboard），6 设备卡片网格 + 摄像头流
- **Expo app**：同样社区视图（响应式网格）
- **实时更新**：每 5 秒轮询 `/api/community/devices`
- **摄像头**：`<img>` 嵌流地址（MJPEG），未到货显示占位图

### 5.3 摄像头"被入侵"效果

设备风险=红时，前端给摄像头卡片叠加红框 + "⚠️ HACKED" 半透明层。

## 6. 实施步骤（分阶段，可独立交付）

| 阶段 | 内容 | 依赖 | 当前可做 |
|------|------|------|---------|
| P1-1 | 后端加 `/api/community/devices` 接口 | 无 | ✅ 现在 |
| P1-2 | 前端加"社区态势"页面（6 设备卡片+风险色） | P1-1 | ✅ 现在 |
| P1-3 | 摄像头卡片加占位图 + 流地址接入 | 无 | ✅ 现在（占位图） |
| P1-4 | 摄像头"被入侵"红框叠加效果 | P1-2 | ✅ 现在 |
| P1-5 | Expo app 同步社区视图 | P1-2 | ✅ 现在 |
| P1-6 | ESP32-CAM 到货后接真实流 | 硬件 | ⏳ 等硬件 |

**P1-1 到 P1-5 现在就能做**（不依赖摄像头硬件），到货后只改一个流地址（P1-6）。

## 7. 设备风险等级 → 颜色映射

| 等级 | 名称 | 颜色 | 边框 |
|------|------|------|------|
| 0 | 正常 | 绿 | 绿色边框 |
| 1 | 侦察 | 黄 | 黄色边框 |
| 2 | 拒绝服务 | 橙 | 橙色边框 |
| 3 | 僵尸网络 | 红 | 红色边框 + "⚠️" |

## 8. 备注

- 设备 IP 需与 `docs/07-device-topology.md` 的 IP 分配一致（192.168.4.10-15）。
- 当前硬件：5 台 ESP32-C3（无 ESP32-CAM），摄像头用占位图。
- 摄像头流地址默认 `http://192.168.4.10:81/stream`（CameraWebServer 默认端口 81）。
